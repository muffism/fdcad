# Documentation and code audit, 2026-11-02

Written by the manager session during the second tutorial review. Research agents read the user guide, the specs and the phase1 code side by side (`origin/phase1` as of 2026-11-02, read only; the app was not run) and listed every place where they disagree, and code that drops input without a message. This file lists defects in what FDCAD already has. New behaviour is in `docs/TUTORIAL_REVIEW_SPEC_2.md`; its section 20 lists the defects found by exercise walk throughs.

Each entry needs a quick check in the app before it is fixed. A separate quality check re-read about 125 of the High and Medium claims in the code: none were wrong, a few were partly right and have been corrected. Paths are under `src/fdcad/`. Severity: **High** gives a wrong result or blocks a common task, **Medium** misleads or silently drops input, **Low** is a missing note or a small mismatch. Where the code is right and the guide is wrong, fix the guide.

Nothing here comes from reference material; it is FDCAD's own code and documents only.

## Read first

The most serious findings, all confirmed by running FDCAD's own core or offscreen UI, unless noted:

1. **Topological naming can silently pick the wrong face or edge (E item 13).** In 14 hard cases (references downstream of cuts, splits, revolves and imports), 17 of 196 references resolved by name to a different face or edge with the feature reported OK, which PLAN.md section 6 item 6 forbids. This is an architecture level problem (CLAUDE.md section 1A suggests Opus for it).
2. Changing the part's units rescales the model when values were typed as bare numbers (D3 item 1).
3. Swept Boss with a twist angle gives wrong volumes, up to 5 percent at 70 mm, and fails at 100 mm, all reported as OK (E item 1, kernel cause in spec 2 section 19).
4. Sweep, Pipe, Thin Feature and Rib drop splines from a path without a message; a spline only path fails with an internal error (E item 4).
5. A feature pasted into another part keeps the source part's face references and can silently cut into an unrelated feature (E item 7.8).
6. Hostile or damaged files: the 3MF reader can hang for hours on a small malformed file and is read on every rebuild; 3MF and embedded data have no decompression limit (D12 items 1 to 3; confirmed with bounded samples).
7. Quitting with several unsaved parts can lose a discarded part's changes after a later Cancel; a cancelled rebuild reports success and Export writes the partial body (E item 12).
8. Edge flanges cannot be mirrored or patterned, and the error advice contradicts itself (E item 7.7).
9. Hole Tool makes holes at construction points; Propagate Colours does nothing; Combine fails silently in two cases; a spline anywhere in a sketch with a crossing fails the whole profile (E item 7).
10. SHORTCUTS.md and the code disagree on Ctrl+Shift+S and many default keys (C items 1 and 2), and the Mac Redo key runs Previous View (spec 2 TR375).
11. Inch clearance hole values do not match the standard the file cites (D13 item 1).

Good news: 1108 dimension edits across all samples lost no references (the samples use only the stable kind of names, so this does not contradict item 1); sheet metal flat lengths, thread geometry, helix and print estimate numbers match the hand formulas; booleans after face merging stayed valid in 21 cases; the node editor works as documented; core never imports Qt, there is no network code, and no file content can run code.

## A. Curves, deform, holes and fastening, sheet metal

### Medium

2. Flatten computes the flat size only when Show bounding box is ticked; the guide says the panel always shows it (`core/features/sheetmetal/flat_pattern.py:202`).
3. Picking a gauge overwrites the typed thickness and radius; choosing No gauge later does not bring them back, though the guide says nothing is lost (`ui/sheet_metal/flow.py:508-520`).
4. Cross Break lines run between the corners of the wall's bounding box, so on an L shaped or notched wall they leave the wall (`core/features/sheetmetal/cross_break.py:41-44`).
5. Array Along Curve ignores ticked features without a message if any body face is picked (`core/features/curve_array.py:302`).
6. The Hole Tool puts holes on construction points and centres of construction circles (`core/features/hole.py:197-212`; the construction flag is `core/sketch/model.py:59`).
7. Forming Tool keeps only lines from its sketch; arcs, circles and splines are dropped without a message (`core/features/sheetmetal/form_tool.py:185-186`).
8. Any sketch entity that fails to convert to an edge is skipped silently in the shared curve helper used by Composite Curve, Projected Curve, Flow, Pipe, Array Along Curve and Contour, giving a shorter curve or a misleading join error (`core/features/curves.py:92-102`).
9. PHASE5_SPEC P5.3 item 1 (edit the flange profile sketch) is not implemented and the guide is silent (`core/features/sheetmetal/edge_flange.py`). TR166 in spec 2 covers the behaviour.

## D. Data exchange (several confirmed by probe scripts run on a scratch copy of the code)

### High

1. DXF: a closed polyline of two vertices with bulges (the usual DXF circle) imports as half an arc (probe confirmed).
2. DXF: circles, polylines and ellipses with a reversed extrusion direction land mirrored with no warning; only arcs are handled (probe confirmed).
3. DXF: joining end points is quadratic; 6000 lines took about 13 seconds in a probe, against the CLAUDE.md section 5A rules.
4. DXF: blocks (INSERT) are skipped and the BLOCKS section is not read, so a drawing made of blocks gives "nothing to insert".
5. DXF: paper space entities, invisible entities and frozen or off layers are imported with model space.
6. STEP import drops wires, curves, points, names, layers, invisibility and curve colours with no report (probe: a solid plus a free edge gave an empty report).
7. STL and OBJ have no unit choice on import; millimetres are assumed (the guide says so, but a file in inches arrives 25.4 times too small with no prompt). PLY is not read at all.
8. OBJ negative (relative) indices are resolved against the total vertex count instead of the current position (probe: faces landed on the wrong group).
9. 3MF read: component objects are skipped ("no triangles"), and an item with a mirror transform imports inside out (probe: negative volume).
10. 3MF write: names are not XML escaped (spec 2 section 20 item 11; probe: a name with an ampersand fails to parse). Confirmed by the manager.

### Medium

11. DXF: polyface meshes and 3D polylines are read as stray lines; one form feed or other line separator character inside a skipped text makes the whole file fail; linetypes are dropped (centre and hidden lines could become construction); spline degree, knots and weights are ignored with no note; Z values are flattened with no warning; the join tolerance is fixed.
12. DXF and SVG export: all on layer 0, no colours, closed outlines not chained into closed polylines or closed SVG paths.
13. STEP export: no part or body names (the product name is a kernel default), no author, no validation properties (volume, area, centroid) that receivers can check; import ignores validation properties.
14. STEP export sets process wide kernel settings (schema and unit), which can race when two exports run on the worker pool; pass them per call.
15. STEP import: colour lookup and duplicate removal are nested searches, quadratic in faces (CLAUDE.md section 5A).
16. STL: empty triangles are removed with no count. OBJ: vertex colours, materials, groups, lines and curves are ignored with no count.
17. 3MF read: support and surface objects import as parts; required extensions are not checked; multi file production models are not read. Supports and surfaces skipped since D733; the rest moved to IDEAS.md item 77 on 2026-11-18.

### Low

18. DXF: more unit codes (micron, nanometre and others), using the measurement header as a hint; old code page text.
19. SVG export reports the full circle size for a partial arc.
20. STEP: hidden bodies arrive visible; mesh only STEP files give "no closed solids" instead of offering mesh import; the import report does not say the file's unit. Hidden bodies and the unit moved to IDEAS.md item 78 on 2026-11-18.
21. STL: colour bytes are ignored silently; a truncated file says "not an STL" instead of "the file ends early".

## D3. App level flows (files, undo, tree, configurations, recovery, node editor)

### High

1. **Confirmed by probe: changing the part's units rescales the model.** Change Units (also the status bar unit button) only sets the part unit, and every stored value text is evaluated again with the part unit. In a probe, a 20 by 10 rectangle extruded "25" (bare numbers) in a mm part became 635 by 254 by 508 mm after switching to inches; values typed with a unit ("25mm") did not change; switching back restored it. PLAN.md section 7 item 1 says the unit change affects display only and never geometry. Fix options: Change Units rewrites bare numbers with an explicit unit, or each value keeps the unit it was typed in (`ui/commands/document.py:398-412`, `core/units/expressions.py:540-542`, `core/equations/engine.py:274`, `ui/main_window/window.py` set_units and toggle_units). This is the most serious finding of the audit.
2. Save runs kernel writes and Python loops over faces on the UI thread (the shape cache store), against CLAUDE.md section 5 item 2 and 5A item 2; big parts freeze on save (`ui/session.py:191-207`, `core/cache/disk.py:84-104`).
3. Pasting a feature into another part keeps the source part's face, edge and feature references and formula owners; only the sketch is copied, so references can point at unrelated features in the target with no message (`ui/main_window/feature_clipboard.py:164-248`, `core/document/paste.py`).

### Medium

4. A cancelled rebuild still reports "Rebuilt in N s", and Export then writes the partial body with no warning; Export also writes a stale body while a newer rebuild runs, or a partial one with errors or the rollback bar up, with no warning (`ui/session.py:292`, `window.py` rebuilt and export).
5. Replacing a feature's named value from the property panel does not rewrite node editor formulas, and undo does not restore them; the Equations dialog rename and delete do not follow graph nodes either (`ui/commands/document.py`, `ui/equations/commands.py`).
6. Delete does not check node editor dependencies: features used by a graph model reference give no warning, and a graph whose position feature is deleted silently moves to the end of the tree (`core/document/dependencies.py`, `core/graph/drive.py:29`).
7. Loading accepts duplicate feature ids, a next id below the highest used, and dangling rollback, graph position and tree ids, so a damaged file can make ids repeat (`core/io/fdef.py:278`).
8. Very deeply nested JSON raises a recursion error that is not caught as a file error (`fdef.py` loads, `window.py` open_path).
9. Recovery: answering No deletes every autosave with no second chance; autosaves that fail to load are never listed or deleted; a recovered part saves over its original even if the disk file is newer (`ui/main_window/recovery.py:103-125`, `window.py` recover).
10. Autosave and import compression run on the UI thread, so large embedded STEP data stalls the UI; autosave failures are swallowed with no sign (`recovery.py:64-73`, `ui/main_window/imports.py`, `core/io/embedded.py:36`).
